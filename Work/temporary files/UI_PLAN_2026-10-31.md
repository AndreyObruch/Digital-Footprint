# Оперативный план-ТЗ: интерфейс агента «Цифровой след»
Дата: 31.10.2026 · Версия: 0.1 · Проект: Digital-Footprint
Назначение: развиваем существующую страницу `/` (поле + карточки) до витрины агента для чемпионата. Заглушки помечены 🔧 — раскрываем по ходу, не выдумывая содержимое.

## Текущая точка (по факту, не по желанию)
Есть: тёмная страница `/` с одним полем вопроса, карточки находок, подсветка совпавших слов, ссылка на первоисточник; `/search` отдаёт JSON; тесты зелёные (store 2/2, search 8/8).
Нет: онбординга, расширенных якорей, состояний «ищем/пусто/ошибка», секции «чего нет» (поле `missing` в записи есть, но UI его не показывает — дефект против правила досье №15), разграничения однофамильцев, диалога-уточнения, сохранения, бренда.

## Принципы интерфейса (вытекают из досье, не обсуждаются на вёрстке)
- Нет источника — нет факта. Каждая находка несёт ссылку на первоисточник.
- «Не найдено» и «чего не хватает» — полноценные состояния, а не ошибка.
- Шум без якоря (27 карточек) показываем как риск, а не как успех: уровень уверенности + уточняющий вопрос.
- Агентность без LLM на этом витке: уточняющие вопросы детерминированы по пустым якорям (LLM-контур отложен, решение №16).
- UI не ломает API: `/search` и `/health` не трогаем, тесты остаются зелёными.

## 7 ближайших шагов (каждый = одно действие, критерий проверяем локально)
1. **Каркас экранов и переходы.** Главная (форма) → Результат (список карточек) → Сохранённое (🔧 пустой список-заглушка). Роуты/секции, навигация. Критерий: три экрана открываются, переходы работают, `/search` не затронут.
2. **Расширенная форма-якорь.** Вместо одного поля — фамилия, имя, отчество, примерный год, место, звание/часть + поле «семейный документ-якорь» (🔧 без загрузки файла, только текст-подсказка). Критерий: форма собирает якоря и передаёт их в `/search` как слова запроса; пустые поля не ломают поиск.
3. **Честные состояния.** «Ищем…» (спиннер/строка), «не найдено» (с подсказкой, какие якоря добавить), «индекс не читается» (ошибка), «мало данных для уверенного ответа». Критерий: каждое состояние видно на реальном запросе и на заведомо чужом; ни одно не имитирует успех.
4. **Карточка находки: полные секции.** «Что найдено» (ФИО/тип/год/место/звание/часть) · «Почему сошлось» (matchedWords + score) · **«Чего нет»** (поле `missing` — сейчас скрыто, закрыть дефект) · ссылка на первоисточник · реквизиты дела (ЦАМО ф./оп./д.). Критерий: на записи кейса №1 видно и «что есть», и «чего нет» (пустой скан, нет боевых точек, пуст год/место рождения).
5. **Разграничение кандидатов.** Список находок с сортировкой по score, метка «возможны однофамильцы» при нескольких совпадениях, кнопка «уточнить» (🔧 ведёт к шагу 6). Критерий: на запросе без якоря список не выдаётся за единственно верный; порядок по score стабилен.
6. **Диалог-уточнение агента (🔧 детерминированный, без LLM).** Если якорей мало или кандидатов несколько — агент задаёт 1 уточняющий вопрос по недостающему полю (напр. «Укажите отчество или примерный год»), а не гадает. Критерий: на «Обруч Николай» без отчества — уточняющий вопрос; на полном ФИО — сразу карточка.
7. **Сохранение/экспорт + бренд-заглушка.** Кнопка «Сохранить находку» (🔧 localStorage, без бэкенда) и «Скачать карточку» (🔧 текст/JSON); шапка с названием-плейсхолдером и слоганом-плейсхолдером (оба не утверждены, помечены 🔧 под замену). Критерий: сохранённое появляется на экране «Сохранённое»; плейсхолдеры визуально отличаются от финального текста, чтобы не принять за решение.

## Правила по шагам
- Один шаг за раз: команда → проверка локально → результат → коммит (текст присылаю) → следующий.
- Заглушку не выдаём за готовое: помечаем 🔧 в коде комментарием и в досье строкой 🔄.
- Не трогаем `/search`, `/health`, `store.js`, тесты — только слой страницы.
- Название/слоган в шаге 7 — плейсхолдеры до утверждения (открытый вопрос досье).

## Открытые вопросы к обсуждению (до начала шага 1)
- Порядок: идём 1→7 линейно или сначала «витрина для жюри» (шаги 3–4–6), потом остальное?
- Диалог-уточнение (шаг 6): детерминированных вопросов достаточно для демо чемпионата, или всё же тянуть LLM-контур (риск egress, решение №16)?
- Сохранение (шаг 7): localStorage как заглушка приемлемо, или сразу бэкенд-хранилище (это уже спринт Г)?
- Бренд: оставляем плейсхолдер до утверждения названия или фиксируем рабочее «Цифровой след» прямо в шаге 7?
